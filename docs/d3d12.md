# Direct3D 12 in wintomac

Status (2026-11-06, third pass): **Shader Model 6.4, feature level 12_0, resource binding tier 3,
asynchronous presentation, graceful fallbacks for what Metal lacks, and the interfaces UE4/UE5/Unity query
at startup.** A real Microsoft sample (`D3D12HelloTriangle`, DXIL shaders) runs unmodified apart from headless
edits.

```
guest d3d12 calls ──> wrapper vtable (Win64 thunks) ──> runtime/d3d12*.c shims ──> libvkd3d (native arm64, patched)
                                                                                 ──> Vulkan loader ──> MoltenVK ──> Metal
guest dxgi calls  ──> DXVK dxgi.dll (recompiled: factory, adapters, outputs, display modes)
                      └─ CreateSwapChainForHwnd(queue) ──> IWineDXGISwapChainFactory on our queue wrapper
                                                         ──> runtime/d3d12_swapchain.c (host IDXGISwapChain4 + presenter thread)
```

## Shader models (measured: `tests/src/dx12_sm6x.c`)

DXC is built from source for macOS (`tools/build_dxc.sh` → `third_party/dxc/build/bin/dxc`, v1.9.2609; ~25 min).
The corpus is `tests/shaders/sm6x/*.hlsl`, compiled into `tests/shaders/dx12_sm6x_blobs.h` by
`tools/gen_dx12_blobs.py` (checked in, so `make check` doesn't need DXC). Each shader's results are compared
with values computed on the CPU.

| feature | SM | status | notes |
|---|---|---|---|
| wave intrinsics (sum, prefix, ballot, read lane, bit ops, ...) | 6.0 | **PASS** | 32 lanes; compute and pixel shaders |
| wave ops in a vertex shader | 6.0 | **PASS** | although MoltenVK lists only frag/compute/tess-control subgroup stages |
| quad ops in a pixel shader | 6.0 | **PASS** | |
| 64-bit integers | 6.0 | **PASS** | |
| SV_ViewID | 6.1 | **PASS** | patched: always view 0 (ViewInstancingTier = NOT_SUPPORTED) |
| SV_Barycentrics / GetAttributeAtVertex | 6.1 | unsupported | vkd3d-shader lacks it; `BarycentricsSupported` = 0 (optional feature) |
| native 16-bit types | 6.2 | not claimed | vkd3d-shader treats 16-bit as 32-bit; `Native16BitShaderOpsSupported` = 0 (optional), so 16-bit storage layouts are wrong if a game ignores the cap |
| dot4add_{i8,u8}packed, dot2add | 6.4 | **PASS** | patched (XeSS's DP4a path uses these) |
| WaveMatch, WaveMultiPrefix* | 6.5 | unsupported | needs a loop emulation (no SPIR-V/Metal equivalent); blocks claiming 6.5 |
| mesh / amplification shaders | 6.5 | unsupported | no mesh shaders in vkd3d or MoltenVK; `MeshShaderTier` = 0 |
| inline ray tracing (RayQuery) | 6.5 | unsupported | `RaytracingTier` = 0 |
| SM 6.6 resource handles (`createHandleFromBinding`/`annotateHandle`) | 6.6 | **PASS** | patched. Every cs/ps/vs_6_6 shader uses these, so this is what makes 6.6 binaries load at all |
| pack/unpack intrinsics, IsHelperLane, [WaveSize(32)] | 6.6 | **PASS** | patched; WaveSize other than 32 is refused (Apple GPUs are 32-wide) |

| dynamic resources (ResourceDescriptorHeap) | 6.6 | unsupported | `createHandleFromHeap` needs a bindless heap layout in libvkd3d |

**Reported shader model: 6.4** (patched in libvkd3d's `CheckFeatureSupport`, so native and recompiled builds
agree). Every required feature of 6.1-6.4 passes; 6.5 lacks WaveMatch/WaveMultiPrefix, 6.6 lacks 64-bit
atomics, dynamic resources and compute derivatives. Queries for 6.8/6.9 (newer SDKs probe downward from their
highest) are answered instead of failing. `WINTOMAC_D3D12_SHADER_MODEL=6.6` still forces a higher report.

## Capability report (patched libvkd3d, MoltenVK 1.4.2, Apple M5)

* **Feature level 12_0.** Upstream libvkd3d capped MoltenVK at 11_0 (no geometry shaders, logic ops, cull distance,
  pipeline statistics or tiled resources). Our patch treats those as individually reported caps instead of feature
  level gates. 12_1 still needs conservative rasterization, which Metal lacks.
* **Resource binding tier 3.** libvkd3d's descriptor heaps are Vulkan descriptor sets with update-after-bind and
  partially bound descriptors; the patch derives the tier from those limits (1M, samplers 500K) instead of the 16
  samplers of plain sets.
* OPTIONS: tiled resources tier 0, conservative rasterization 0, ROVs 1, typed UAV loads 1, raytracing 0, VRS 0,
  mesh shaders 0, sampler feedback 0, enhanced barriers 0, view instancing 0, root signature 1.1, wave ops 1 (32).
* UMA is reported 0: MoltenVK exposes a device-local-only (private) memory type besides the shared one, and the
  discrete-GPU path is the better-tested one in engines.

## Workarounds for missing Metal / MoltenVK features (`runtime/d3d12_pso.c`, `tests/src/dx12_gs_fallback.c`)

| feature | MoltenVK | what we do | fidelity |
|---|---|---|---|
| geometry shaders, pass-through shaped | none | the GS is dropped, the PSO draws without it. "Pass-through shaped" = one primitive in, the same out (`maxvertexcount` = input vertices, matching output topology), no GS instancing, no layer/viewport/primitive-ID outputs, outputs a subset of the previous stage's (checked with vkd3d-shader's disassembler and signature scan, DXBC and DXIL) | exact for true pass-through GS; approximate if the GS edits vertices (e.g. flat normals) |
| geometry shaders, anything else (point sprites, layered/cube rendering, extrusion) | none | the PSO is created (without GS and PS) and every draw with it is skipped; logged | no crash, the geometry is missing |
| stream output | no transform feedback | SO declaration removed; with a rasterized stream the draws render normally, capture-only PSOs skip their draws; SO buffers stay unwritten | rendering correct, captured data absent |
| predication | no conditional rendering | predicated draws/dispatches always execute (logged once) | correct images, no occlusion culling saving |
| depth clip disable | no `depth_clip_enable` | libvkd3d's depth-clamp path (`DepthClipEnable=FALSE` → depth clamp); verified: a triangle beyond the far plane is drawn | matches D3D except for depth values outside [0,1] being clamped |
| custom border colours | no `custom_border_color` | arbitrary `D3D12_SAMPLER_DESC` border colours snap to the nearest of transparent black / opaque black / opaque white (alpha, then luminance); UINT border colours of `CreateSampler2` map 0/1 | approximate for unusual colours |
| null descriptors | no `nullDescriptor` | libvkd3d emulated NULL buffer and 2D views with 1x1 resources; our patch adds 1D, 3D and cube (previously such descriptors were left unwritten, so a stale or destroyed view could be read) | reads zero, as on Windows; 2D-MS null views are still unwritten |
| tiled / reserved resources | no sparse binding | `TiledResourcesTier` = 0, `CreateReservedResource(1,2)` fail cleanly; tile mapping calls are no-ops | games must take their non-tiled path (most check the tier) |
| ray tracing, mesh shaders, VRS, sampler feedback, work graphs | none | reported unsupported; state objects / `SetProgram` / `DispatchGraph` fail or no-op with a log | engines take their non-RT / vertex-pipeline paths |
| enhanced barriers | n/a | `OPTIONS12.EnhancedBarriersSupported` = 0; `ID3D12GraphicsCommandList7::Barrier` still works (layouts / access bits translated to legacy transitions and UAV barriers) | approximate synchronisation scopes |

Environment: `WINTOMAC_D3D12_GS=strip|skip` forces a GS mode; `WINTOMAC_D3D12_FAKE_NO_GS=1` applies the GS
fallbacks on drivers that have geometry shaders (testing).

## Presentation (`runtime/d3d12_swapchain.c`)

* **Asynchronous.** Present signals a fence on the game's queue and queues the frame for a presenter thread (as in
  Wine's dxgi), which waits for the fence, blits the back buffer into the `VkSwapchainKHR` and presents. The game's
  thread only waits (a) before reusing a back buffer whose blit isn't on the GPU queue yet and (b) for the frame
  latency limit (`SetMaximumFrameLatency`, default 3) unless the game paces itself with the waitable object.
* **Waitable object**: an auto-reset event plus a counter of frames that may start (max latency minus frames in
  flight); the presenter thread signals it as frames complete. Measured: with latency 1 and 2, no frame starts with
  more frames in flight than allowed.
* `WINTOMAC_DXGI_SYNC_PRESENT=1` (read when the swapchain is created) restores synchronous presentation.
* **Measured** (`WINTOMAC_BENCH=1 build/dx12_async_present.bin`, hidden 512x512 window, Present(0), 6 ms of CPU
  work + a heavy pixel shader per frame, Apple M5):

  | mode | ms/frame |
  |---|---|
  | synchronous (before) | 12.5 |
  | asynchronous | 8.5 |
  | asynchronous, no CPU work (GPU-bound floor) | 8.46 |

  The CPU work is now completely hidden behind the GPU.
* Back buffers, formats, fullscreen and the rest are unchanged from the second pass: VkImages on libvkd3d's device
  wrapped with `vkd3d_create_image_resource` (RGBA8/BGRA8 ± sRGB, RGB10A2, RGBA16F); FIFO, or IMMEDIATE for sync
  interval 0; `VK_SUBOPTIMAL_KHR` is success; fullscreen = borderless window at the display mode via user32.
* Not implemented (logged once): HDR colour spaces (`SetColorSpace1` ≠ sRGB fails; `IDXGIOutput6::GetDesc1`
  reports SDR), `SetSourceSize` scaling, Present1 dirty rects, frame statistics (DISJOINT), swapchain private data.
  If a game closes the waitable handle while frames are in flight, the presenter may signal a recycled handle.

## Breadth (`runtime/d3d12_ext.c`, `tests/src/dx12_breadth.c`)

* **QueryInterface** of every wrapped object goes through `d3d12_qi`: `ID3D12Device1..14`,
  `ID3D12GraphicsCommandList1..10`, `ID3D12Heap1`, `ID3D12Resource1/2`, `ID3D12Fence1` all answer with the same
  object. Guest vtables are libvkd3d's interfaces plus the newer methods (`GUEST_EXTRA` in `tools/gen_d3d12.py`,
  order as in Microsoft's DirectX-Headers). Unknown IIDs are logged once with their GUID.
* **ID3D12Device10..14**: `CreateCommittedResource3`, `CreatePlacedResource2`, `CreateReservedResource2`
  (barrier layouts → initial states; castable formats ignored), `CreateSampler2`, `GetResourceAllocationInfo3`;
  `OpenExistingHeapFromAddress1` and `CreateRootSignatureFromSubobjectInLibrary` return E_NOTIMPL.
  `ID3D12Device9::CreateCommandQueue1` (stubbed in libvkd3d) creates a normal queue.
* **ID3D12GraphicsCommandList7..10**: enhanced `Barrier`, `OMSetFrontAndBackStencilRef` (front value),
  `RSSetDepthBias` / `IASetIndexBufferStripCutValue` (logged), `SetProgram` / `DispatchGraph` (no-ops).
* **Helper objects**: `ID3D12InfoQueue(1)` (empty queue; filters, breaks and callbacks accepted),
  `ID3D12DeviceRemovedExtendedData(1,2)` (outputs `DXGI_ERROR_NOT_CURRENTLY_AVAILABLE`), DRED settings via
  `D3D12GetDebugInterface` / `D3D12GetInterface(CLSID_D3D12DeviceRemovedExtendedData)` (accepted, no-op), the no-op
  `ID3D12Debug..6` from the second pass. `D3D12GetInterface` for SDK configuration / device factory / tools and
  `D3D12EnableExperimentalFeatures` return E_NOINTERFACE ("no Agility SDK").
* **DirectStorage**: `DStorageGetFactory` returns E_NOTIMPL with a NULL factory (titles fall back to Win32 I/O).
* **DXGI 1.6** (DXVK 1.10.3's `dxgi.dll`, verified): `IDXGIFactory6::EnumAdapterByGpuPreference`,
  `IDXGIAdapter4::GetDesc3`, `IDXGIOutput6::GetDesc1` (SDR, 8 bpc), `CheckHardwareCompositionSupport`,
  `IDXGIFactory5::CheckFeatureSupport(ALLOW_TEARING)` = TRUE. Note: DXVK reports `DedicatedVideoMemory` = 0 on
  Apple's unified memory, which some games treat as "no GPU memory".
* Still not provided: `ID3D12PipelineLibrary` (libvkd3d returns DXGI_ERROR_UNSUPPORTED, which engines handle),
  state objects, meta commands, protected sessions, `ID3D12CommandQueue1`, `ID3D12Resource3`, lifetime trackers.

## Real programs

`make dx12-sample` builds Microsoft's **DirectX-Graphics-Samples `D3D12HelloTriangle`** (MIT; sparse clone in
`third_party/dx-samples`) with mingw (`tools/build_dx_samples.py`, DirectX-Headers instead of the NuGet Agility
SDK, shaders compiled to DXIL with our DXC), recompiles it with DXVK's `dxgi.dll` and runs 60 frames in a hidden
window: `HelloTriangle: 1280x720, centre 127,64,64,255 corner 0,51,102,255` (the expected vertex-colour mix and
clear colour). The build copy gets headless edits only: hidden window, a fixed frame loop, a readback at the end,
and `WINVER=0x0601` because the runtime has no `CreateFile2` yet.

To watch it in a window (it is hidden in the build): in `build/samples/HelloTriangle/Win32Application.cpp`,
change `ShowWindow(m_hwnd, SW_HIDE)` to `ShowWindow(m_hwnd, SW_SHOW)` and the 60-frame loop bound to a larger
number, then `make build/hellotriangle.bin` (or rerun the recompile/link lines of `make dx12-sample`) and run
`cd build/samples/HelloTriangle && ../../hellotriangle.bin D3D12HelloTriangle.exe`.

## libvkd3d patches (`third_party/vkd3d-patches/`, applied by `tools/build_vkd3d.sh`)

1. `0001` vkd3d-shader/dxil: `createHandleFromBinding` + `annotateHandle` (SM 6.6 binaries), `[WaveSize]`,
   `pack4x8` / `unpack4x8`, `dot4AddI8Packed` / `dot4AddU8Packed`, `dot2AddHalf`, `viewID`.
2. `0002` capability reporting: shader model 6.4, binding tier 3 from update-after-bind limits, feature level 12_0.
3. `0003` NULL 1D / 3D / cube SRVs without `nullDescriptor`.

`tools/build_vkd3d.sh` extracts the release tarball into `third_party/vkd3d/work`, applies the patches, builds,
installs into `work/stage` (DESTDIR) and only then copies the result over `third_party/vkd3d/install`, which every
game links. `--stage` stops before the copy, for testing with `DYLD_LIBRARY_PATH=<stage>/lib` (set it after any
SIP-protected launcher such as `perl`, which strips `DYLD_*`). Development happens in a git checkout
(`third_party/vkd3d/dev`), exported with `git format-patch`.

descriptors). Wine's vkd3d needs none of these.

## How the layer works (`runtime/d3d12.c`, `d3d12_ext.c`, `d3d12_pso.c`)
* **Wrappers.** The guest sees `{ guest_vtbl*, host*, magic, ..., xflags }`, cached per host pointer, so
  `GetDevice` / `QueryInterface` return the same pointer. `AddRef`/`Release` forward to libvkd3d. `xflags` carries
  per-object state of the workarounds (PSO "skip draws", the list's current PSO).
* **Generated shims** (`tools/gen_d3d12.py` → `runtime/gen/d3d12_thunks.h`): every method of the most-derived
  interface libvkd3d implements (`ID3D12Device9`, `ID3D12GraphicsCommandList6`, `ID3D12Resource2`, ...): Win64 args
  (floats from xmm0-3), unwrapping interface args and arrays, wrapping interface results.
* **Hand-written shims**: argument structs with embedded interfaces (barriers, copy locations, render passes,
  PSO descs and streams), QueryInterface, CheckFeatureSupport, draws / PSO binding (skipping), samplers, the newer
  interfaces' methods.
* **Exports**: `D3D12CreateDevice`, root signature (de)serialisers, `D3D12GetDebugInterface`, `D3D12GetInterface`,
  `D3D12EnableExperimentalFeatures`; `DStorage*` stubs.
* **Vulkan**: libvkd3d gets the host loader through a `vkGetInstanceProcAddr` wrapper adding
  `VK_KHR_portability_enumeration`, plus surface/Metal-surface and swapchain extensions for DXGI.
* **Logging**: `WINTOMAC_D3D12_TRACE=1` traces every call; unimplemented / approximated paths are logged once.

## What still blocks UE4 / UE5 / Unity D3D12 titles
1. **UE5's SM6 path needs SM 6.6** with 64-bit atomics (Nanite, VSM) and, for bindless, dynamic resources.
   MoltenVK has no 64-bit atomics, so Nanite can't run; UE5 titles that ship only SM6 shaders won't start
   (`WINTOMAC_D3D12_SHADER_MODEL=6.6` lets them try; shaders using those features fail to compile). UE5 titles with
   SM5/DX11-class fallbacks and UE4 (SM5 DXBC) are in reach.
2. **WaveMatch / WaveMultiPrefix** (SM 6.5) and **compute derivatives** (SM 6.6): emulation needed in vkd3d-shader.
3. **Geometry shaders beyond pass-through** (UE's cube-map / layered passes, some Unity effects): their draws are
   skipped. A real emulation (compute pre-pass or VS-instancing rewrite) is the next big item; layered rendering
   with a constant layer could use `VK_EXT_shader_viewport_index_layer`, which MoltenVK has.
4. **Raytracing / mesh shaders / VRS**: reported unsupported; engines with a raster fallback are fine.
5. **libvkd3d limits**: `ExecuteIndirect` supports only single-argument signatures without count buffers (no
   `draw_indirect_count` in MoltenVK either) — GPU-driven renderers (UE5 Nanite/Lumen, Unity's GPU resident drawer)
   need more; no pipeline libraries; less game-tested than vkd3d-proton.
6. **DXGI**: `DedicatedVideoMemory` = 0 from DXVK on unified memory; no HDR.
7. **Runtime**: `CreateFile2` has no kernel32 shim (seen with the Microsoft samples).
